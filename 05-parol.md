# Задание 5. Пароль на виду

1. `bash -c 'exec -a "db-backup --password=SuperSecret123" sleep 300' &` - имитируем программу, которой пароль передали аргументом командной строки.
```
[1] 1403
```
процесс запущен в фоне, `PID 1403`.

2. `ps aux | grep -- --password` - поиск процессов с строкой `password`
```
$ ps aux | grep -- --password
user        1403  0.0  0.0   6012  2304 pts/0    S    04:10   0:00 db-backup --password=SuperSecret123 300
user2       1430  0.0  0.0   6676  2444 pts/1    S+   04:12   0:00 grep -- --password
```
под пользователем `user2` видна вся командная строка процесса user, включая `--password=SuperSecret123`

3. `cat /proc/$(pgrep -f SuperSecret)/environ` - попытка прочитать окружение процесса, от другого пользователя
```
cat: /proc/1403/environ: Отказано в доступе
```
чужой пользователь получает Permission denied, тогда как cmdline был виден.

### В отчет (05-parol.md):

- объясните, почему cmdline доступен всем, а environ — нет;
> `/proc/PID/cmdline` содержит аргументы запуска и по умолчанию читаем всем. `/proc/PID/environ` содержит переменные окружения, поэтому ядро отдаёт его только владельцу процесса и root
- сформулируйте правило: как правильно передавать пароль программе (переменная окружения, файл конфигурации с правами 600, интерактивный ввод) и почему не аргументом:
1. не передавать пароль аргументом командной строки (он виден в `ps`/`/proc/*/cmdline` всем). Правильно будет через интерактивный ввод (`read -s`)
