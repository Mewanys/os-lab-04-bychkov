# Задача 4. Нехватка памяти и OOM

1. Создание файла
```
  GNU nano 8.4                                        /home/user/eat.py *                                                
chunks = []
mb = 0
try: 
    while True:
        chunk = bytearray(10*1024*1024)
        for i in range(0, len(chunk), 4096):
            chunk[i] = 1
        chunks.append(chunk)
        mb += 10
```
скрипт в цикле выделяет по 10 МБ
2. `( ulimit -v 307200; python3 ~/eat.py )` - запускаем скрипт в подоболочке с лимитом виртуальной памяти
```

```
процесс дошёл примерно до 280 МБ и упал с MemoryError

ядро зафиксировало OOM и убило python3.


### В отчёт ( 04-oom.md ):
- что делает ulimit -v и почему этот способ безопаснее запуска без лимита:
> адаёт максимальный размер виртуальной памяти (адресного пространства) для процесса и его потомков. Без лимита процесс растёт, пока не кончится RAM/swap, и тогда ядро запускает OOM killer, который может убить любой процесс.
- как ядро выбирает жертву, когда память кончается у всей системы (по лекции);
> OOM killer оценивает каждый процесс по oom_score. У процесса с наибольшим oom_score шанс быть убитым выше
- что такое oom_score и где его посмотреть ( cat /proc/PID/oom_score ).
> oom_score — числовая оценка кандидата на убийство, которую ядро вычисляет для каждого процесса. Смотреть бесплатно: cat /proc/PID/oom_score
